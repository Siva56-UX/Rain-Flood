# สิงห์บุรี เฝ้าระวังน้ำ

หน้าประชาชนสำหรับคนทั่วไปและผู้สูงวัย พร้อมพยากรณ์ฝนและแนวโน้มปริมาณน้ำ **วันพรุ่งนี้ถึงอีก 7 วัน** สำหรับ 6 อำเภอของสิงห์บุรี

## ใช้งาน

ใช้ Node.js 22.13 ขึ้นไป (ตรวจสอบด้วย Node 24)

```sh
npm ci
npm run dev
```

เปิด http://localhost:3000 เลือกอำเภอ โดยไม่ต้องสร้างบัญชีหรืออนุญาตตำแหน่ง GPS

สำหรับใช้งานแบบ production บน Node server:

```sh
npm run build
npm start
```

การเปลี่ยนแปลงนี้ยังไม่ได้ติดตั้งบนเว็บสาธารณะ และไม่มีการเปลี่ยนสิทธิ์การเข้าถึง Sites

## ฟังก์ชันที่มีโค้ดและใช้งานได้ในรุ่นนี้

- หน้า `/`: เลือกและจดจำอำเภอ, ปุ่มขยายตัวหนังสือ 125%, ปุ่มฟังสรุปภาษาไทยและหยุดเสียง, ช่องทางติดต่อช่วยเหลือ
- พยากรณ์ฝน: ปริมาณฝนและโอกาสฝนสูงสุดรายวันจาก Open-Meteo
- แนวโน้มน้ำ: ค่าเฉลี่ยและช่วงเปอร์เซ็นไทล์ 25–75 ของปริมาณน้ำไหลจาก GloFAS ผ่าน Open-Meteo; ไม่มีการแปลงเป็นระดับน้ำหรือโอกาสน้ำท่วมรายบ้าน
- `/api/forecast?area=1701`: ตรวจสอบอำเภอ, เรียกแหล่งข้อมูลแยกกัน, จับคู่ด้วยวันที่, ตรวจหน่วยและค่าที่หายไป, cache ในหน่วยความจำ 15 นาที, จำกัดการลองใหม่หลังล้มเหลว, รวมคำขอที่เกิดพร้อมกัน
- ข้อมูลเก่าจะมีป้ายชัดเจนและหยุดแสดงเมื่อดึงไว้นานเกิน 6 ชั่วโมง; ไม่เติมค่าศูนย์หรือข้อมูลจำลองแทนข้อมูลขาด
- `/api/alerts?area=1701`: ตัวอ่านประกาศทางการแบบ opt-in; เมื่อไม่ได้ตั้งแหล่งข้อมูลจะแสดง “ยังไม่ได้เชื่อมประกาศอัตโนมัติ” พร้อมลิงก์หน่วยงาน
- แสดงประกาศเตือนหรือรายงานน้ำท่วมที่ยังใช้ได้เด่นในสรุป; ประกาศกับพยากรณ์เป็นคนละส่วน
- หมายเลขโทรศัพท์: ปภ. 1784, แพทย์ฉุกเฉิน 1669, ปภ.สิงห์บุรี 036-507-129 พร้อมแหล่งอ้างอิง
- หน้าเว็บขอข้อมูลทุก 1 นาทีขณะเปิด; พยากรณ์ใช้ cache 15 นาที ส่วนประกาศใช้ cache 1 นาที นี่ไม่ใช่งานส่งเตือนเบื้องหลัง

## สิ่งที่ต้องเข้าใจก่อนใช้ข้อมูล

1. `floodRisk` เป็น `unknown` เสมอ ไม่มีแบบจำลองน้ำท่วมรายบ้านที่ปรับเทียบแล้ว ค่าฝนเป็นโอกาสฝน ไม่ใช่โอกาสน้ำท่วม
2. พิกัดใน `lib/resident-model.ts` เป็นจุดอ้างอิงโดยประมาณของอำเภอ ไม่ใช่ตำแหน่งสถานีแม่น้ำที่ยืนยันแล้ว ไม่มีขอบเขตน้ำท่วม
3. GloFAS มีความละเอียดประมาณ 5 กม. อาจเลือกสาขาแม่น้ำผิด ต้องตรวจสอบกับข้อมูลสถานีและภูมิศาสตร์ก่อนใช้ตัดสินใจในพื้นที่
4. ข้อมูลฝนเป็นวันตาม Asia/Bangkok; ข้อมูลน้ำเป็นวันตาม UTC และไม่ได้ถือว่าเป็นช่วง 24 ชั่วโมงเดียวกัน
5. เวลา “ดึงข้อมูล” ไม่ใช่เวลาออกผลแบบจำลอง API ที่ใช้นี้ไม่มีเวลาออกผลในคำตอบ; ข้อมูล 7 วันอาจมีบางวันขาด และไม่มีการเติมค่าที่หายไป
6. Cache อยู่ในแต่ละ process และหายเมื่อ restart ไม่ใช่ cache ร่วมทั้งระบบ ก่อนรองรับทั้งจังหวัดควรมี shared cache และการจำกัดอัตราที่จุดให้บริการ
7. เสียงอ่านต้องมีเสียงภาษาไทยติดตั้งบนอุปกรณ์ หากไม่มีจะมีคำแนะนำและยังอ่านข้อความได้ ไม่มีการส่งเสียงไป Messenger
8. ยังไม่ได้ต่อข้อมูลวัดจริง ThaiWater/RID, ตรวจสอบระดับตลิ่ง, ศูนย์พักพิงหรือเส้นทางอพยพ, และไม่มีบริการส่งข้อความฉุกเฉิน

## ประกาศทางการ (เลือกเปิดเมื่อตรวจสอบ feed แล้ว)

คัดลอก `.env.example` เป็น `.env.local` แล้วตั้ง `OFFICIAL_ALERT_FEED_URL` เฉพาะเมื่อได้ยืนยันกับเจ้าของแหล่งข้อมูลแล้ว ไม่ตั้งค่าตัวอย่างเป็นแหล่งจริง และห้าม commit ค่าลับ

ตัวอ่านรองรับ JSON รูปแบบเดียวกับโครงการเดิม:

```json
{
  "alerts": [
    {
      "id": "example-revision-only",
      "areaId": "1701",
      "level": "watch",
      "text": "ตัวอย่างรูปแบบเท่านั้น ไม่ใช่ประกาศจริง",
      "sourceName": "ชื่อหน่วยงาน",
      "sourceUrl": "https://sbr.disaster.go.th/ddpmsing/home",
      "issuedAt": "2026-09-25T08:00:00Z",
      "expiresAt": "2026-09-25T09:00:00Z"
    }
  ]
}
```

- ตรวจพื้นที่, วันออกประกาศไม่เกิน 6 ชั่วโมง, ไม่อยู่ในอนาคต, วันหมดอายุ, ระดับที่รองรับ และไม่ซ้ำ ID
- ทั้ง URL feed และ URL ต้นฉบับต้องเป็น HTTPS ของ `disaster.go.th`, `tmd.go.th`, `rid.go.th`, `thaiwater.net`, `singburi.go.th` หรือ subdomain ของหน่วยงานดังกล่าว และไม่ใช้ redirect
- การอยู่ในโดเมนที่อนุญาตไม่ใช่หลักฐานว่าผู้เผยแพร่มีอำนาจออกคำเตือน ผู้ดูแลต้องตรวจสอบก่อนตั้งค่า
- เมื่อโหลดล้มเหลวจะไม่ใช้ประกาศเก่าแทนประกาศปัจจุบัน และไม่แสดง “ปลอดภัย” จากการไม่มีประกาศ
- รุ่นนี้ไม่มีหน้าเพิ่มประกาศของผู้ดูแลและไม่มี endpoint เขียนข้อมูล
